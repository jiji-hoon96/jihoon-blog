# hreflang 수정 전 검색 기준선 (2026-09-11)

2026-09-11 에 카테고리 페이지의 hreflang 클러스터와 x-default 를 고쳤다.
(커밋 `0f49582`, `7307f43`) 효과는 Google 이 새 annotation 을 다시 읽어야
나타나므로 2주에서 4주 뒤에 비교한다. 이 문서는 그 비교 대상이다.

원본 CSV 는 `.gsc-data/baseline-20260911/` 에 있다. 그 디렉터리는 gitignore
대상이라 로컬에만 있고, `pnpm gsc` 를 다시 돌려도 덮어쓰이지 않는다.

## 무엇을 고쳤나

카테고리 이름은 로케일마다 번역된다. `AI` 와 `IA`, `관측` 과 `observabilidad`
가 같은 카테고리다. 그런데 hreflang 을 만드는 코드가 카테고리 이름을 문자열로
비교해서, 이름이 우연히 같은 로케일끼리만 서로를 알았다.

그래서 `/es/posts/IA` 는 자기 자신과 `pt-BR` 만 alternate 로 선언했고,
x-default 를 `languages.ko` 로 정하는 줄은 비한국어 페이지에서 항상 비어 있었다.
프로덕션 sitemap 288개 URL 중 97개가 x-default 없이 색인된 상태였다.
`src/app/sitemap.ts` 와 카테고리 페이지가 같은 방식으로 틀려 있었다.

수정 후 빌드 산출물 실측은 이렇다. sitemap 288개 전부 x-default 보유,
비상호참조 0건, self-reference 누락 0건, HTML 과 sitemap 의 클러스터 불일치 0건.

## 다시 볼 때 확인할 것

**영어 페이지의 클릭.** en 글이 892회 노출에 클릭 0 이다. (처음 이 문서에는 895 로 적었는데, en 홈 2회와 방명록 1회를 글로 함께 센 값이었다. 2026-09-16 에 CSV 를 다시 집계해 고쳤다) 평균 순위는 6.5 에서
12.3 사이라 검색 결과 1페이지에 뜨고 있는데도 그렇다. hreflang 이 깨져 있으면
Google 이 검색자의 언어에 맞는 버전을 고르지 못하므로, 한국어 검색자에게 영어
페이지를 보여주는 일이 생긴다. 수정이 반영되면 여기가 먼저 움직여야 한다.

**카테고리가 본문을 이기는 현상.** 쿼리 `querykey` 에서 노출 순위는
`/es/posts/queryKey` 9회, `/ja/260104` 2회, `/en/260104` 1회다. 스페인어
카테고리 목록이 영어와 일본어 본문보다 많이 노출된다. 로케일 클러스터가
이어지지 않은 상태의 증상으로 보인다.

**카테고리 페이지.** 2026-09-11 에 글 1개짜리 카테고리 126개(21개 카테고리 x
6개 로케일)를 `noindex, follow` 로 돌리고 sitemap 에서도 뺐다. 판단 근거는
같은 날 수집한 이 데이터다. 카테고리 페이지 전체의 28일 성과가 노출 62, 클릭 0
이었고, 쿼리 `querykey` 에서는 `/es/posts/queryKey`(노출 9)가 본문인
`/ja/260104`(2)와 `/en/260104`(1)보다 많이 노출되고 있었다.

글이 2개 이상인 42개는 그대로 색인한다. sitemap 은 288개에서 162개로 줄었다.
이 변경도 hreflang 수정과 같은 구간에 들어가므로 10월 비교에서 개별 기여는
분리되지 않는다.

**이것이 en 클릭 0의 원인이라고 확인된 것은 아니다.** 한국어가 아닌 로케일 페이지가 전부

잘림 가설과 반대 방향이다. 세 변경이 같은 구간에 들어갔으므로 10월 비교에서는
개별 기여를 분리할 수 없다. 방향만 본다.

## 다시 수집하는 방법

```bash
pnpm gsc
```

`.env` 의 `GOOGLE_SERVICE_ACCOUNT_EMAIL`, `GOOGLE_PRIVATE_KEY`, `GSC_SITE_URL`
를 쓴다. 결과는 `.gsc-data/` 에 덮어쓰이므로, 비교가 끝나면 그때의 CSV 도
날짜 디렉터리로 복사해 둔다.

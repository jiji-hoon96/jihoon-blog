이번 포스팅에서는 이 블로그의 글 구조에 대한 이야기를 해보려고 한다.

이 글은 이 블로그에 글을 쓰거나 기존 글을 고치는 사람을 위한 샘플이다. 소제목, 목록, 그림, 표, 인용을 각각 어떤 마크다운으로 쓰는지 한 편 안에서 전부 보여준다. 다 읽고 나면 새 글의 뼈대를 이 글에서 그대로 복사해 시작할 수 있다.

필자가 이 글을 만든 이유는 글마다 같은 역할에 서로 다른 마크다운을 써 왔기 때문이다. 공개 글 29편을 세어 보니 굵은 글씨 한 줄을 소제목처럼 쓴 글이 8편, 본문에 구분선을 직접 넣은 글이 6편, 목록 항목의 라벨 표기가 섞인 글이 16편이었다.

## 소제목의 위계

이 블로그의 소제목은 세 단계다. `##` 은 챕터, `###` 은 챕터 안의 절, `####` 은 절 안의 작은 제목이다. 글 제목은 프론트매터의 `title` 이 맡으므로 본문에 `#` 을 쓰지 않는다.

| 마크다운 | 역할 | 목차 | 화면 |
|---|---|---|---|
| `##` | 챕터 | 들어간다 | 32px. 두 번째부터 위에 짧은 구분선 |
| `###` | 절 | 들어간다 | 24px |
| `####` | 절 안의 작은 제목 | 들어가지 않는다 | 18px |

### 챕터와 절

챕터는 독자가 그 지점에서 가질 질문 하나에 답한다. 챕터 하나가 질문 둘을 다루기 시작하면 `###` 으로 나눈다. 반대로 `###` 이 하나뿐인 챕터는 그 `###` 을 걷어내고 챕터 본문으로 올린다.

`##` 앞에 `---` 를 넣지 않는다. 두 번째 챕터부터는 CSS 가 구분선을 자동으로 그린다. 직접 넣으면 구분선이 두 줄이 된다.

#### 번호를 붙이지 않는 이유

`### 1. 인라인 배열` 처럼 소제목에 번호를 붙이면 목차에도 번호가 그대로 실린다. 그런데 목차는 이미 순서대로 나열되므로 번호가 정보를 더하지 않는다.

순서 자체가 논지라면 소제목 번호가 아니라 첫 문단에서 "다섯 가지 방법을 단순한 것부터 본다"처럼 문장으로 밝힌다. 번호는 번호 목록에만 쓴다.

### 작은 제목과 굵은 문장

굵은 글씨만 있는 줄은 쓰지 않는다. 그 줄 아래로 문단이 둘 이상 이어지면 `####` 을 쓰고, 한 문단짜리 요점이면 그 문단의 첫 문장을 볼드로 쓴다.

**판별은 아래 문단 수로 한다.** 굵은 글씨 한 줄은 화면에서 문단으로 렌더되어 목차에도 안 잡히고 소제목 간격도 받지 못한다. 그래서 소제목처럼 보이지도 않고 문단처럼 읽히지도 않는다.

고치기 전의 모양이다.

```markdown
**1. 객체의 키 순서는 무관하다.**

queryKey 안의 객체는 키 순서와 상관없이 같은 키로 본다.
```

고친 뒤의 모양이다. 아래 문단이 하나라서 `####` 이 아니라 볼드 첫 문장으로 올렸다.

```markdown
**객체의 키 순서는 무관하다.** queryKey 안의 객체는 키 순서와 상관없이 같은 키로 본다.
```

## 목록의 순서

번호 목록과 하이픈 목록은 같은 왼쪽 선에서 시작하고 간격도 같다. 다른 것은 표지 하나, 회색 번호와 작은 점이다. 그래서 어느 쪽을 쓰느냐가 곧 "이 항목들에 순서가 있다"는 신호가 된다.

### 순서가 있는 단계

항목의 순서를 바꾸면 뜻이 달라질 때 번호 목록을 쓴다. 한글 원문을 고친 뒤 번역본을 맞추는 절차가 그런 예다.

1. `index.md` 를 고친다.
2. 번역본 5개의 해당 문단을 같이 고친다.
3. 새 해시를 구해 `content/translations.json` 과 번역본 5개의 `sourceHash` 를 갱신한다.
4. `pnpm content:translations` 로 확인한다.

### 순서가 없는 나열

순서를 바꿔도 뜻이 같으면 하이픈 목록을 쓴다. `*` 는 쓰지 않는다. 중첩은 한 단계까지만 쓴다.

- 코드 블록
- 표
- 그림
  - 직접 그린 개념 다이어그램
  - 출처에서 내려받은 원본 그림

중첩이 두 단계 필요해지면 바깥 항목을 `####` 으로 올린다.

### 라벨 붙은 항목

항목마다 이름이 있으면 라벨만 볼드로 쓰고 콜론으로 설명과 나눈다. 콜론은 볼드 밖에 붙이고 앞에 띄어쓰기를 하지 않는다.

- **그림**: 텍스트로 두 문단이 걸리는 구조를 한 장으로 보여줄 때 쓴다.
- **표**: 값을 나란히 놓고 비교할 때 쓴다.
- **인용**: 원문의 말이 논지를 직접 뒷받침할 때만 쓴다.

설명이 두 문장을 넘으면 목록이 아니라 문단이나 `####` 으로 올린다.

## 본문 밖의 요소

소제목과 목록이 글의 뼈대라면 그림, 표, 코드, 인용은 그 사이에 들어가는 근거다. 각각 놓는 자리와 쓰는 문법이 정해져 있다.

### 그림

그림은 본문 문단 사이에 독립된 줄로 둔다. alt 는 그림을 못 보는 독자가 읽어도 내용이 전달되게 문장으로 쓴다. 폭은 `?w=720` 으로 맞춘다.

![왼쪽에 던진 자리 일곱 개가 세로로 놓이고 오른쪽에 도착지 두 개가 있다. 렌더 중, useEffect 안, startTransition 안, lazy 의 import 거부 넷은 파란 화살표로 ErrorBoundary 로 가고, onClick 핸들러 안, setTimeout 콜백 안, Promise 거부 셋은 회색 화살표로 window 로 간다](1.png?w=720)

그림은 [에러 전이 글](/251117)에서 가져왔다.

출처가 있는 그림은 이렇게 그림 바로 아래 독립된 줄에 출처와 라이선스를 적는다. 본문 괄호에 넣지 않는다.

### 표

표는 값을 나란히 비교할 때만 쓴다. 판단과 이유는 표 밖의 문단에 쓴다. 셀이 두 문장을 넘으면 열을 나누거나 문단으로 내린다.

| 요소 | 쓰는 것 | 쓰지 않는 것 |
|---|---|---|
| 순서 있는 나열 | `1.` | 순서 없는 나열에 `1.` |
| 순서 없는 나열 | `-` | `*` |
| 라벨 | `**라벨**:` | `**라벨** :`, `**라벨.**` |

### 코드

코드 블록에는 언어 이름을 붙인다. 고치기 전과 후를 비교할 때는 블록 두 개를 문단 하나로 잇고, 각 블록 앞에 무엇이 달라졌는지 한 문장을 둔다.

```tsx
<Button onClick={handleSubmit}>제출</Button>
```

### 인용

외부 원문은 원문과 번역을 함께 싣는다. 영어 원문은 손대지 않고, 번역은 필자가 한다. 인용 블록은 글 하나에 3~5개를 넘기지 않고, 인용 블록 사이에는 필자의 문단을 최소 하나 둔다.

React 문서는 `ErrorBoundary` 가 받지 않는 에러를 이렇게 적었다.

::::quote
:::translation
이벤트 핸들러, 서버 렌더링, `ErrorBoundary` 자신이 던진 것, 비동기 코드(예를 들어 `setTimeout` 이나 `requestAnimationFrame` 콜백); 예외가 하나 있는데 `useTransition` 훅이 돌려주는 `startTransition` 함수다. 그 transition 함수 안에서 던진 것은 Error Boundary 가 잡는다.
:::

:::original
Event handlers, Server side rendering, Errors thrown in the error boundary itself (rather than its children), Asynchronous code (e.g. `setTimeout` or `requestAnimationFrame` callbacks); an exception is the usage of the `startTransition` function returned by the `useTransition` Hook. Errors thrown inside the transition function are caught by error boundaries
:::
::::

사실만 전달하면 될 때는 인용 블록 대신 인라인 링크를 걸고 필자의 문장으로 푼다.

### 용어 해설

독자에게 낯선 핵심어는 첫 의미 있는 등장에만 해설을 붙인다. :term[RUM]{key="rum"} 처럼 쓰면 용어 해설 패널이 열린다. 해설 패널을 열지 않아도 문장이 읽혀야 한다.

## 결론

이 블로그의 글 구조는 역할마다 마크다운 요소 하나로 정해져 있다. 소제목은 `##`, `###`, `####` 세 단계이고 번호를 붙이지 않는다. 목록은 순서가 있을 때만 번호를 쓰고, 라벨은 볼드로 쓰고 콜론으로 설명과 나눈다. 구분선은 CSS 가 그리므로 본문에 쓰지 않는다.

새 글을 쓴다면 이 파일을 복사해 소제목만 바꾸는 데서 시작하면 된다. 기존 글을 고친다면 굵은 글씨 한 줄과 본문의 `---` 부터 찾아보길 권한다.

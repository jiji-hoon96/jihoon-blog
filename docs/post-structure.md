# 글 구조 규칙

글마다 같은 역할에 다른 마크다운을 쓰고 있었다. 렌더링 스타일은 `src/styles/prose.css` 에 이미 있으므로
이 문서는 **역할마다 마크다운 요소 하나**를 정한다. 소제목 문구 기준(명사구, 20자)은 CLAUDE.md 를 따르고
여기서는 다루지 않는다. 소제목 개수와 밀도도 기준이 아니다.

## 역할표

| 역할 | 쓰는 것 | 쓰지 않는 것 |
|---|---|---|
| 글 제목 | 프론트매터 `title` | 본문의 `#` |
| 챕터 | `##` | `##` 앞의 `---` (CSS 가 두 번째 `##` 부터 구분선을 자동으로 넣는다) |
| 하위 절 | `###` | `### 1. 제목` 처럼 번호 붙이기 |
| 절 안의 작은 제목 | `####` (목차에 들어가지 않는다) | 굵은 글씨만 있는 한 줄 `**1. 제목**` |
| 순서가 있는 단계 | `1.` | 순서 없는 나열에 `1.` 쓰기 |
| 그 밖의 나열 | `-` | `*` |
| 라벨 붙은 항목 | `- **라벨.** 설명` | `**라벨** :`, `**라벨**:` |
| 구분선 | 쓰지 않는다 | `---` |

## 판단 기준

**`####` 과 굵은 글씨 한 줄.** 그 줄 아래에 문단이 둘 이상 이어지면 `####` 이다.
한 문단짜리 요점을 강조하는 것이면 문단 첫 문장을 볼드로 쓴다. 볼드만 있는 줄을 따로 두지 않는다.

**`1.` 과 `-`.** 항목의 순서를 바꾸면 뜻이 달라지는가로 고른다. 실행 절차, 처리 단계, 시간 순서는 `1.` 이다.
`1.` 은 왼쪽 막대가 붙은 단계 스타일로 렌더되어 무겁다. 순서 없는 나열에 쓰면 그 무게가 거짓 신호가 된다.

**라벨 붙은 항목.** 라벨 뒤에는 마침표를 쓰고 볼드 안에 넣는다. 콜론은 쓰지 않는다.
설명이 두 문장을 넘으면 목록이 아니라 문단이나 `####` 로 올린다.

**중첩 목록.** 한 단계까지만 쓴다. 두 단계가 필요하면 바깥 항목을 `####` 로 올린다.

**도입부 구분.** 도입부와 첫 `##` 사이에 `---` 를 넣지 않는다. 첫 `##` 이 그 역할을 한다.

## 샘플

`docs/post-structure-sample.md` 가 위 규칙을 전부 한 번씩 쓴 글 한 편이다. 소제목 세 단계, 번호 목록,
하이픈 목록과 중첩, 라벨 항목, 그림과 출처 줄, 표, 코드, 원문과 번역을 함께 싣는 인용, 용어 해설,
참고 자료를 담았다. 새 글은 이 파일을 복사해 시작하고, 기존 글은 이 모양에 맞춘다.

로컬에서 화면으로 보려면 임시 글로 복사해 개발 서버를 띄운다. 확인한 뒤에는 지운다.

```bash
mkdir -p content/991231 && cp docs/post-structure-sample.md content/991231/index.md
cp content/251117/1.png content/991231/
pnpm dev   # http://localhost:3000/991231
rm -rf content/991231 public/content/991231
```

## 그 밖의 요소

**그림.** 문단 사이 독립된 줄에 두고 `?w=720` 으로 폭을 맞춘다. alt 는 그림을 못 보는 독자에게 내용이 전달되는 문장으로 쓴다. 출처와 라이선스는 그림 바로 아래 독립된 줄에 적는다.

**표.** 값을 나란히 비교할 때만 쓴다. 판단과 이유는 표 밖 문단에 쓴다.

**코드.** 언어 이름을 붙인다. 전후 비교는 블록마다 앞에 무엇이 달라졌는지 한 문장을 둔다.

**인용.** 외부 원문은 `::::quote` 안에 `:::translation` 과 `:::original` 을 함께 싣는다. 글 하나에 3~5개를 넘기지 않는다.

**용어 해설과 참고 자료.** `:term[]{key=""}` 는 첫 의미 있는 등장에만 쓴다. `:::ref` 는 글 맨 끝에 하나만 두고 본문에 인라인으로 건 링크는 넣지 않는다.

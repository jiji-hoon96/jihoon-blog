## 0. 세션 시작 시 순서 (이대로 먼저 할 것)

```bash
# 1) 사용자가 무엇을 고쳤는지 본다 (요약)
./docs/research/diff-since-snapshot.sh --stat

# 2) 실제 변경 내용을 본다 (전체 diff)
./docs/research/diff-since-snapshot.sh

# 3) 스냅샷 무결성 확인이 필요하면
cd docs/research/snapshot-20260816 && shasum -a 256 -c MANIFEST.sha256
```

기준선은 `docs/research/snapshot-20260816/` 이고 2026-08-16 검증 직후 상태다. `content/` 와 `docs/research/` 는 git 미추적이라 이 스냅샷이 유일한 diff 기준이다. **`CLAUDE.md` 와 `.claude/commands/*` 는 git 추적 대상이지만 현재 커밋되지 않은 수정이 얹혀 있으므로, `git diff` 가 아니라 이 스냅샷과 비교해야 사용자 변경만 분리된다.**

diff 를 읽은 뒤에는 아래 3절(재검증)을 **반드시** 돌린다. 사용자가 문장을 고치면서 수치나 인용이 함께 움직였을 수 있다.

## 2. 사용자 변경을 읽을 때의 관점

diff 를 단순히 "무엇이 바뀌었나"로 읽지 말고 아래를 함께 판단한다.

1. **사용자가 되돌린 것이 있는가.** 2026-08-16 에 반영한 수정 중 사용자가 원래대로 돌려놓은 것이 있으면 그것은 취향 표명이다. **다시 바꾸지 말고 `HANDOFF.md` §5(바꾸지 말 것)에 항목을 추가한다.**
2. **사용자가 새로 쓴 문장에 검증되지 않은 주장이 있는가.** 수치, 날짜, 외부 인용, "~라고 한다" 형태의 서술이 새로 들어왔으면 3절 규칙으로 확인한다.
3. **사용자 문장과 도표가 어긋나지 않는가.** 본문 수치를 고치면 `content/260703/*.png` 안의 숫자도 같이 고쳐야 한다. 도표는 스크린샷이라 자동으로 따라가지 않는다. **HTML 원본은 `docs/research/figures/` 에 보존해뒀다.** 해당 HTML 을 고치고 `./render.sh <이름> <높이>` 로 다시 구운 뒤 `content/` 로 복사하면 된다. 파일명과 PNG 번호 매핑은 그 디렉터리의 `README.md` 에 있다.
4. **문체 이동.** 사용자가 고친 문장의 어투가 기존 글과 다르면 그쪽이 사용자의 실제 목소리다. 가이드를 사용자 쪽에 맞춰 갱신하는 것을 검토한다.

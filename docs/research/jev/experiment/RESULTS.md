# 결과

> 2026-09-22. Apple M2 Max 64GB, Kev-9B (`jaredpalmer/kev-9b`), bf16, MPS.
> 절차와 집합 구성은 `README.md` 에 있다.

## 먼저 밝힐 것

**이것은 Kev 다. Jev 가 아니다.** early access 를 받지 못해 공개 재현 구현을 돌렸다.
아래 숫자를 Jev 의 숫자로 인용하면 틀린다.
Kev 는 Qwen3.5-9B-Base 에 rank-16 LoRA 와 pointer head 를 얹은 것이고,
학습 데이터는 영어 결정 과제다. TypeSafe 문서도 Jev 에 대해 이렇게 적는다.

> English is the primary training language and where accuracy is currently best.
> Other languages, including CJK scripts, are handled but not equally well.

**유효 표본은 문장 수가 아니라 단어 수다.** 라벨이 단어 단위로 정해지므로
같은 단어가 나오는 문장들은 독립 관측이 아니다. 게이트 집합은 24종, 보류 집합은 13종이다.
아래 표에 둘 다 적었다.

## 한 줄

**5% 오차 예산에서 자동 처리할 수 있는 결정이 한 건도 없었다.** 양쪽 집합 모두 `coverage_at_5pct_error = 0.0` 이다.

## 무슨 일이 일어났는가

질문마다 갈라 본다. `report.json` 의 `tasks` 는 noul 세 개를 하나로 묶으므로 행에서 직접 갈랐다.

| 질문 | 집합 | 정확도 | 라벨 분포 | 모델의 예측 분포 |
|---|---|---|---|---|
| `convert_noul` | 게이트 | 0.225 | false 79 / true 23 | **false 0 / true 102** |
| `convert_noul` | 보류 | 0.500 | false 30 / true 30 | **false 0 / true 60** |
| `keep_noul` | 게이트 | 0.745 | false 23 / true 79 | false 9 / true 93 |
| `keep_noul` | 보류 | 0.683 | false 30 / true 30 | false 11 / true 49 |
| `convert_choice` | 게이트 | 0.304 | english 23 / hangul 79 | english 88 / hangul 14 |
| `convert_choice` | 보류 | 0.500 | english 30 / hangul 30 | english 50 / hangul 10 |

**`convert_noul` 은 162문장 전부에 「되돌려야 한다」고 답했다. 예외가 없다.**
단어 37종 전부, 문장 전부다.

| | 양성 (되돌려야 함) | 음성 (그대로 둬야 함) |
|---|---|---|
| 게이트 집합 | 23/23 정답 | **0/79 정답** |
| 보류 집합 | 30/30 정답 | **0/30 정답** |

그래서 보류 집합의 0.504 는 실력이 아니다. 집합이 균형 잡혀 있어서 나온 숫자다.
단어별 평균 확률은 0.70 에서 0.95 사이이고 라벨과 아무 상관이 없다.

`keep_noul` 의 0.745 도 실력이 아니다. 그쪽도 대부분 「예」라고 답하는데(93/102)
그 집합의 다수 라벨이 마침 true(79)여서 높게 나왔다.

`convert_choice` 는 상수가 아니다. 게이트 집합에서 14문장을 `hangul` 로 답했다.
상수였다면 0.225 나 0.775 가 나와야 하는데 0.304 다. **같은 판단인데 프리미티브에 따라 흔들린다.**

근거는 표준편차가 아니라 **음성 0/109 라는 사실**이다. 같은 단어 안 예측의 표준편차 평균은
0.046(게이트)과 0.068(보류)로 작다.

**다만 이것을 「문장을 못 읽는다」의 근거로 쓰면 안 된다.** 아래 ctx 실행이 반박한다.
같은 단어와 같은 문장에 참고 자료만 더했더니 문장마다 예측이 흩어졌다.

| 단어 | 참고 없이 편차 | 참고와 함께 편차 |
|---|---|---|
| 로더 | 0.096 | 0.217 |
| 뮤테이션 | 0.042 | 0.236 |
| 스테이트 | 0.016 | 0.152 |
| 티어링 | 0.061 | 0.176 |

**문장은 읽는다.** 참고 없이 편차가 작았던 것은 상수 응답의 결과이지 문장을 안 본다는 증거가 아니다.

## 편향인가 무지인가

「무엇을 물어도 예라고 하는 모델」이라면 결과가 무의미하다. 확인했다.

| 상태 / 질문 | 물은 것 | 답 |
|---|---|---|
| 한국어 / 한국어 | 이 문장은 영어로 쓰여 있는가? | 0.02 |
| 한국어 / 한국어 | 이 문장은 요리법을 설명하는가? | 0.04 |
| 한국어 / 한국어 | 이 문장에 숫자가 들어 있는가? | 0.02 |
| 한국어 / 한국어 | 이 문장은 한국어로 쓰여 있는가? | 0.98 |
| 한국어 / 한국어 | 이 문장은 소프트웨어를 설명하는가? | 0.96 |
| 한국어 / 영어 | Is this sentence written in English? | 0.01 |
| 영어 / 영어 | Is this sentence written in Korean? | 0.03 |
| 영어 / 영어 | Is this sentence about software? | 0.96 |

**한국어를 읽고, 「아니오」를 말하고, 0.02 와 0.98 을 정확히 가른다.**
그러니 실패는 언어 문제도 순응 편향도 아니다. 이 과제에 한정된다.

그렇다면 규칙의 앞부분(「음차는 되돌린다」)만 집행하고 예외 조항을 버리는 것인가.
그러려면 적어도 문장은 읽고 있어야 한다. 그것부터 확인했다.

### 기계가 확인할 수 있는 질문도 못 맞힌다

`compound` 질문은 「이 문장에서 이 단어가 언제나 더 긴 합성어의 일부로 등장하는가」를 묻는다.
정규식이 정확히 답할 수 있는 표면적 성질이다.

**먼저 내 라벨의 버그를 밝힌다.** 처음 붙인 라벨은 한국어 조사를 합성으로 오판했다.
`리렌더링을` 의 `을` 을 뒤따르는 한글로 보고 합성어라고 표시했다.
게이트 집합 38개, 보류 집합 25개가 그렇게 뒤집혀 있었다. 조사를 떼고 다시 계산했다.
라벨은 채점에만 쓰이고 모델에 전달되지 않으므로 응답을 다시 받을 필요는 없었다.

| | 고친 라벨의 양성 | 다수 클래스 기준선 | 모델 | 모델의 true 예측 |
|---|---|---|---|---|
| 게이트 집합 | 4/102 | 0.961 | 0.529 | 46/102 |
| 보류 집합 | 5/60 | 0.917 | 0.417 | 36/60 |

실제로 합성어인 문장이 5% 인데 모델은 45% 에 그렇다고 답한다.
**다만 이 질문은 시험이 되지 못한다.** 고친 라벨의 양성이 4개와 5개뿐이라 다수 기준선이 0.96 과 0.92 다.
그 아래 어떤 값이 나와도 「기준선에 못 미친다」 이상은 말할 수 없다.
그래서 이 결과를 해석의 근거로 쓰지 않는다. 기록으로만 남긴다.

정확하게 말할 수 있는 것은 이것뿐이다. **이 질문 형태에 대해 내용과 거의 무관한 상수를 낸다.**
왜 그런지는 밖에서 알 수 없다.

그래도 시험해 볼 것이 하나 남는다. 판별에 필요한 지식을 `state` 로 직접 주면 달라지는가.
**답은 아니오였다.** 아래 「참고 자료를 state 에 넣으면」을 보라.

## ECE 는 과신 한 덩어리다

두 집합 모두 `ECE ≈ confidence_bias` 다.

| | ECE | 과신 | 잔차 |
|---|---|---|---|
| 게이트 집합 | 0.3701 | 0.3701 | 0.0000 |
| 보류 집합 | 0.2567 | 0.2408 | 0.0159 |

Jev 를 영어 스위트 일곱 개에서 잰 값도 같은 구조다(잔차 0.002~0.011, 도시에 7.2).
**miscalibration 이 구간마다 흩어진 잡음이 아니라 전 구간에 걸친 균일한 위쪽 이동이다.**
규모만 다르다. Jev 는 0.011~0.105, 여기서는 0.257~0.370 이다.

## 구조적 항등식은 성립하지 않는다

| | 게이트 집합 | 보류 집합 |
|---|---|---|
| `P(되돌린다) + P(그대로)` 평균 | 1.655 | 1.508 |
| 범위 | 1.25 ~ 1.91 | 0.86 ~ 1.88 |
| 합이 1에서 0.1 넘게 벗어난 문장 | 102/102 (100%) | 59/60 (98%) |
| Noul 과 Choice 의 결론 불일치 | 14/102 (14%) | 10/60 (17%) |
| 두 확률의 평균 절대차 | 0.195 | 0.183 |

**놀랄 일이 아니다. 설계가 그렇다.** 질문끼리 서로 읽지 못하므로 두 질문의 확률이 1로 합쳐질 이유가 없다.
TypeSafe 도 `model-jaggedness` 페이지에 `refund` 0.72 + `not_refund` 0.47 = 1.19 를 실었다.
여기서 재현된 것은 같은 현상이고 더 크다.

**실무 함의는 하나다.** Noul 에 맞춰 조율한 임계값을 Choice 로 옮기면 안 된다.
결론이 갈리는 문장이 14~17% 다.

## 참고 자료를 state 에 넣으면

TypeSafe 문서가 권하는 도메인 적응 방식이다. 가중치를 건드리지 않고 request 로 준다.

> Put your proprietary content, records, and reference material in the `state` field.

`write-post.md` 에 이미 적혀 있는 규칙 문단을 `state` 에 함께 넣고 다시 돌렸다.
입력이 문장당 100토큰에서 450토큰으로 늘었다.

**게이트 집합은 누출이다.** 그 참고 자료가 게이트 단어 8개와 예외 단어 여럿을 이름으로 나열한다.
그래서 「state 를 읽을 수는 있는가」를 보는 양성 대조군으로만 쓴다.
**진짜 시험은 보류 집합이다.** 그 13개 단어는 참고 자료에 한 번도 나오지 않는다.

| | 게이트 (누출) | 게이트 +참고 | 보류 | 보류 +참고 |
|---|---|---|---|---|
| 전체 정확도 | 0.422 | 0.645 | 0.504 | 0.496 |
| `convert_noul` | 0.225 | 0.676 | **0.500** | **0.500** |
| 양성 정답 | 23/23 | **1/23** | 30/30 | 8/30 |
| 음성 정답 | 0/79 | 68/79 | 0/30 | 22/30 |
| true 예측 비율 | 102/102 | 12/102 | 60/60 | 16/60 |
| 단어 단위 정확도 | 6/24 | | 7/13 | **5/13** |
| ECE | 0.370 | 0.199 | 0.257 | 0.231 |
| 평균 확신도 | 0.792 | 0.840 | 0.745 | 0.726 |
| 5% 예산 자동화 비율 | 0.000 | 0.066 | 0.000 | 0.021 |
| 지연 중앙값 | 2,924ms | 6,903ms | 2,908ms | 6,918ms |

### 답은 아니오다

**균형 잡힌 보류 집합에서 정확도가 0.500 에서 0.500 으로, 한 치도 움직이지 않았다.**
단어 단위로 보면 7/13 에서 5/13 으로 오히려 내려갔다.

게이트 집합의 0.225 → 0.676 은 실력 향상이 아니다. **모델이 상수를 바꿨을 뿐이다.**
전에는 102문장 전부에 「되돌린다」고 했고, 참고 자료를 주자 12문장에만 그렇게 답했다.
음성이 0/79 에서 68/79 로 올랐지만 양성이 23/23 에서 **1/23** 으로 무너졌다.
그 집합은 음성이 79대 23으로 많으므로 「대체로 두라」는 상수가 자동으로 더 높은 점수를 받는다.
보류 집합은 30대 30이라 그 속임수가 통하지 않고, 그래서 0.500 이 그대로 나왔다.

**구별을 배운 것이 아니라 기울기를 바꾼 것이다.**

### 그래도 한 가지는 좋아졌다

구조적 항등식이 눈에 띄게 회복됐다.

| | 참고 자료 없이 | 참고 자료와 함께 |
|---|---|---|
| 게이트: `P(되돌린다)+P(그대로)` 평균 | 1.655 | **1.032** |
| 게이트: 합이 1에서 0.1 넘게 벗어난 문장 | 102/102 | 33/102 |
| 게이트: Noul 과 Choice 결론 불일치 | 14/102 | 5/102 |
| 보류: 합 평균 | 1.508 | **0.963** |
| 보류: 벗어난 문장 | 59/60 | 18/60 |
| 보류: Noul 과 Choice 불일치 | 10/60 | 8/60 |

**균형 집합 한 줄로 끝난다.** 보류 집합에서 합이 1.508 에서 0.963 으로 붙었는데
정확도는 0.500 에서 움직이지 않았다. 두 질문의 확률이 서로 맞아떨어지는 것과
그 확률이 맞는 것은 다른 일이다.

게이트 집합에서는 정확도도 같이 올랐지만 그것은 사전확률이 뒤집힌 결과이므로
이 논증에 끌어들이지 않는다.

### 5% 예산은 여전히 0에 가깝다

0.000 에서 0.066(누출된 집합)과 0.021(보류)로 올랐다. 100건 중 두 건을 자동 처리할 수 있다는 뜻이다.
**규칙을 글로 줘도 이 판단은 자동화 경계를 넘지 못했다.**
그리고 그 대가로 지연이 2.4배(2.9초 → 6.9초) 늘었다.

## 이 실험이 말하지 않는 것

- **Jev 의 성능.** 위에 적은 대로 Kev 다.
- **이 과제가 어떤 결정 모델로도 안 된다는 것.** 한 모델, 한 프롬프트, 162문장이다.
- **한국어에서 결정 모델이 쓸모없다는 것.** 진단 표가 보여주듯 쉬운 한국어 판단은 정확하다.
- **5% 예산 0.0 을 다른 문헌의 0.70/0.45 와 비교하는 것.** 언어도 과제도 다르다. 같은 축이 아니다.

## 이 실험이 말하는 것

1. **모델이 이 과제를 전혀 못 하면서 확신도는 0.79 로 돌려준다.** 확률이 「나는 이걸 모른다」를
   말하지 못한다. 자동화 비율 0.0 은 임계값을 아무리 높여도 5% 오차를 못 맞춘다는 뜻이다.
2. **그래서 `confidence` 필드로 선을 긋는 통합은 여기서 조용히 79건을 잘못 고친다.**
   확신도 0.9 이상이 게이트 집합에서 28%인데 그 구간의 실제 적중이 0.425 다.
3. **`probabilities` 와 `confidence` 는 다른 물건이라는 것이 여기서 눈에 보인다.**
   분포가 한쪽으로 몰려 있으니 `confidence` 는 높게 나온다. 몰려 있는 것과 맞는 것은 다르다.
   TypeSafe 어댑터 소스가 그 산식을 그대로 보여준다(`typesafe-confidence_metrics.py`).
4. **규칙을 글로 줘도 안 된다.** 참고 자료를 `state` 에 넣자 예측이 문장마다 흩어졌으니
   모델은 문장을 읽는다. 그런데 균형 집합 정확도는 0.500 에서 0.500 그대로였다.
   **읽기는 하는데 구별을 못 한다.** 같은 실행에서 구조적 항등식만 회복됐다(합 1.508 → 0.963).
5. **정규식이 이긴다.** 게이트 집합에서 1.000 대 0.422 다. 기계가 확실히 할 수 있는 절반은
   기계에게 두는 편이 낫다. 모델이 들어갈 자리는 목록이 못 덮는 나머지인데, 거기서 이 모델은
   기준선을 넘지 못했다.

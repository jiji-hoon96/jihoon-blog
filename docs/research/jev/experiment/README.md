# 음차 판별 실험

> 이 리포에 실제로 있는 판단 하나를 결정 모델에 넘겨 보고, 돌아온 확률로 선을 그을 수 있는지 잰다.
> 2026-09-22. Apple M2 Max 64GB.

## 왜 이 판단인가

`content/terminology.yml` 의 `banned` 목록이 음차 외래어를 막는다. 지금 15개이고 그중 음차는 8개다.
목록을 넓히지 못한 이유가 `.claude/commands/write-post.md` 에 적혀 있다.

> 게이트에 올리지 않는 것은 두 가지 이유에서다.
> 첫째, 합성어 안에 들어가면 치환이 문장을 부순다. (...)
> 둘째, 한국어 기술 문서에서 이미 정착한 말이 있다.

**기계가 하는 절반은 정규식이고, 나머지 절반은 사람이 한다.** 그 나머지 절반이 System One 과제의 모양이다.
답이 둘뿐이고, 아는 사람은 1초에 판단하고, 아무도 안 보는 자리에서 돌아야 한다.

## 집합 두 개

### 게이트 집합 (`loanword_eval.jsonl`, 91개)

게이트가 이미 아는 단어다. 정규식이 100% 맞힌다. 통제군으로 둔다.

- **양성 26개.** 본문이 영어로 쓴 게이트 단어 6종(`calendar`, `picker`, `adapter`, `headless`, `locale`, `timezone`)을
  한글 음차로 되돌린 반사실 문장. 게이트가 막는 것이 정확히 이 형태다.
- **음성 65개.** `write-post.md` 가 예외로 명시한 음차 18종이 실제로 쓰인 문장. 단어당 최대 4개.

### 보류 집합 (`loanword_heldout.jsonl`, 67개)

**게이트가 한 번도 본 적 없는 단어다.** 여기서 정규식은 양성을 하나도 못 잡는다.

라벨의 근거는 필자의 의견이 아니라 **리포가 그 단어를 일관되게 어느 표기로 쓰는가**다.

| 라벨 | 근거 | 단어 |
|---|---|---|
| 양성 35개 | 본문이 영어로만 쓴다(한글 음차 0회) | `loader` `mutation` `blob` `prefill` `tearing` `bailout` `props` `state` |
| 음성 32개 | 본문이 한글로만 쓴다(영어 0회) | 리듀서 스냅샷 게이트웨이 런타임 번들 스트림 |

둘 다 쓰거나 빈도가 낮은 단어는 라벨을 세울 수 없으므로 뺐다(`caching`/캐싱, `prompt`/프롬프트, `query`/쿼리 등).

## 무엇을 묻는가

한 요청에 질문 넷을 담는다. 그래야 같은 실행에서 네 가지를 동시에 잰다.

| 질문 | 타입 | 재는 것 |
|---|---|---|
| `convert_noul` | noul | 정확도와 캘리브레이션 |
| `keep_noul` | noul | 그 부정. `P(A) + P(¬A)` 가 1이 되는지 |
| `convert_choice` | choice | 같은 판단을 Choice 로 물었을 때 결론이 갈리는지 |
| `compound` | noul | 문서가 적은 판별 기준을 모델이 따라오는지 |

`compound` 의 라벨은 문장에서 그 단어가 언제나 더 긴 한글 덩어리 안에 있는지로 기계가 계산한다.

## 모델

Kev-9B (`jaredpalmer/kev-9b`), Qwen3.5-9B-Base + rank-16 LoRA + pointer head, bf16, MPS.
Jev 에 early access 가 없어 공개된 재현 구현을 쓴다. **Jev 자체가 아니다.**
Kev README 가 적은 Jev 와의 차이(새 출처 정확도 0.857 대 0.822, 5% 예산 자동화 비율 0.70 대 0.45~0.57)를
이 결과에 그대로 얹어 읽으면 안 된다. 그 숫자는 영어 과제의 것이다.

## 채점

Kev 자신의 채점기를 쓴다. 지표 정의가 README 표와 같아진다.

```bash
uv run python -m kev.benchmark --remote http://127.0.0.1:8009 \
  --data <records.jsonl> --out runs/<name>
```

보는 것은 accuracy, Brier, ECE, 그리고 `coverage_at_error`(5% 오차 예산에서 자동 처리할 수 있는 비율)다.
마지막 것이 이 글의 논점이다. 정확도가 아니라 **선을 그을 수 있는가**를 재기 때문이다.

## 미리 적어 두는 예상과 반증 조건

결과를 보고 해석을 맞추지 않기 위해 먼저 적는다.

1. **게이트 집합에서 정규식이 Kev 를 이긴다.** 이기지 못하면 집합 구성이 잘못된 것이다.
2. **보류 집합에서 정규식은 양성 35개를 전부 놓친다.** 정의상 그렇다.
3. **Kev 는 보류 집합에서 다수 클래스 기준선(0.52)을 넘지 못할 수 있다.**
   영어 결정 과제로 학습한 LoRA 이고, TypeSafe 문서도 CJK 가 영어만큼은 아니라고 적었다.
   넘지 못하면 그것이 결과다. 그때는 자동화 비율이 0 에 가까워야 정직한 모델이다.
   **정확도가 낮은데 자동화 비율이 높게 나오면 확률이 거짓말을 하고 있는 것이다.**
4. **`P(convert) + P(keep)` 은 1에서 벗어난다.** TypeSafe 가 영어 문서에 실은 1.19 와 같은 현상이
   한국어에서도 나오는지 본다.
